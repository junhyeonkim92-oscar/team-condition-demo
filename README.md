# 팀 컨디션 보드 (가칭)

겨울스포츠 팀 지도자가 **선수 12명의 오늘 컨디션을 한 화면에서 확인**하는 코치용 대시보드입니다.
헤이제임스 8주 프로그램 **1주차 제출물** — 1차 프로젝트(축소판)의 첫 화면입니다.

**라이브 데모** → https://team-condition-demo.surge.sh

---

## 무엇을 해결하나

현장 지도자는 선수 컨디션을 카톡·구두·수첩으로 따로따로 받습니다.
누가 오늘 안 좋은지 알려면 대화방을 거슬러 올라가야 하고, 기록은 남지 않습니다.

이 서비스는 **선수가 아침 30초 입력 → 코치는 한 화면에서 확인**으로 그 과정을 대체합니다.

| | |
|---|---|
| 누가 | 겨울스포츠 실업·대표팀 지도자 (성인 선수 대상) |
| 어떤 문제 | 선수 컨디션 정보가 흩어져 있고 기록으로 남지 않음 |
| 어떻게 | 선수 30초 자가입력 → 코치 대시보드에 신호로 정렬 |

## 화면 구성

- **오늘의 팀 현황** — 입력 완료 인원 / 컨디션 신호 / 통증 보고 건수 / 팀 평균 훈련부하(ACWR)
- **선수 로스터** — 신호 순 정렬, 수면·주관 피로도·통증·훈련부하·마지막 입력 시각
- **신호 기준 안내** — 양호 / 주의 / 확인 필요 / 미입력 4단계 판정 근거 명시
- **입력률 추이** — 최근 14일 팀 평균 (서비스 지속의 핵심 지표)

## 이 화면의 설계 원칙

1. **부상을 판정하지 않습니다.** 신호는 수면·피로도·통증·훈련부하의 *변화 폭*을 표시하는 모니터링 지표이며,
   최종 판단은 지도자·의무팀이 합니다. 화면 하단에 이 범위를 명시했습니다.
2. **성인 선수 대상 B2B**입니다. 미성년 생체정보는 v1 범위에서 제외했습니다.
3. **표시된 선수 정보는 전부 가명·예시값**입니다. (BS-014 김○○ 형태)


## 3주 로드맵 (1차 프로젝트)

| 주차 | 범위 |
|---|---|
| 1주차 | 화면 확정 · 데이터 모델 설계 · 배포 파이프라인 (**현재 지점**) |
| 2주차 | 선수 입력 폼 + 저장 + 로그인 · 코치 화면을 실데이터로 연결 |

## 기술 스택

현재 화면은 의존성 없는 정적 HTML/CSS 입니다.
2주차부터 서버·DB를 붙이며, 건강 관련 정보는 **국내 서버 저장 + 별도 동의** 전제로 설계합니다.
